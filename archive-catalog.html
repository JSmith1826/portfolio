Independent project · ongoing

Building a catalog that can be corrected without losing its history.

A collection of sports programs and publications began as thousands of handwritten notecards. I’m turning those cards into a structured, reviewable working catalog.

The problem

OCR can accelerate transcription, but it also introduces uncertain titles, names, dates, and catalog numbers. A spreadsheet alone makes it hard to preserve the scan as evidence, correct repeated errors consistently, or tell who changed a record.

The initial baseline contains 9,039 notecards. Its audit found 457 duplicate catalog-number groups affecting 938 cards. Those are review leads, not assumptions that the underlying items are duplicates.

What the system does

  • Assigns a stable record ID from each raw image’s SHA-256 fingerprint.
  • Preserves original OCR and parsed values alongside corrected fields.
  • Stores review decisions and field-level history in SQLite.
  • Groups recurring team-name variants for human-approved normalization.
  • Keeps ambiguous names unresolved until context supports a decision.

Designed for careful review

The desktop review tool shows a scanned card beside the current catalog interpretation. A reviewer can correct a record, verify it, defer it, and see its edit history. Separate tools support team-name normalization and reference matching.

This is ongoing work. The private scans and database are not published here, and I’m not presenting the catalog as a finished public library.

Why it matters

The useful result is a process that can improve over time. Raw material stays intact; record identity stays stable; repeated names can be resolved once with context; and every accepted correction remains traceable.

The project draws on Python, SQLite, OCR cleanup, data modeling, and practical interface design.
